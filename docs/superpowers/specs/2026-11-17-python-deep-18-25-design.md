## Що будуємо

## Цілі

- Кожен урок має метафору (рядок `/* Ідея: … */`), 1–2 відступи з поясненням «чому» після кожної відповіді, хоча б одну пастку, вікторину й підсумок; наприкінці — посилання «До задачника» на потрібну тему.
- Задачник: умова, блок «Вхідні дані» (змінні лише для читання), редактор, «Запустити» (видно свій вивід), «Перевірити» (3–5 прихованих наборів даних, зокрема крайні), повідомлення, на якому наборі програма помиляється (показуються вхідні дані й очікуване/отримане), підказка, прогрес у `localStorage`, звіт «розв'язав чи розв'язала N з M» з кнопкою «Скопіювати звіт».
- Кожна задача з ноутбуків підписана «Задача: Крутяк Н. О.» з посиланням на папку; задачі, яких у неї немає, — без підпису авторки.
- Логіка, яку можна перевірити без браузера (семантика зрізів і `range`, симуляція методів списків, порівняння виводу, дані задач), — у модулях JS з тестами vitest.
- Очікувані відповіді в задачах не вписані вручну: їх видає еталонний розв'язок, запущений справжнім CPython (скрипт, див. нижче).

## Не-цілі

- Не замінювати ЄPython/Colab як середовище для великих програм: редактор задачника — проста `textarea` з моноширинним шрифтом, Tab = 4 пробіли, номери рядків необов'язкові.
- Без `input()` у задачах: дані задаються змінними, як у ноутбуках.
- Без серверної частини, акаунтів і збору результатів — звіт учень копіює сам.
- Теми після 25 (while, рядки, множини, сортування, жадібні, RLE, JavaScript) — поза межами цього етапу; формат задачника має дозволяти додати їх пізніше лише даними.

## Анти-цілі

- Сторінка уроку, яка не працює без Pyodide. Уроки мусять повністю працювати без інтернету до CDN; запуск коду там — бонус.
- Перевірка, яку можна «обдурити» друком очікуваного рядка: приховані набори даних обов'язкові.
- Завислий браузер від нескінченного циклу: код учня виконується у Worker з тайм-аутом.
- Факт, що суперечить CPython 3 (наприклад, `-7 // 2`).

## Python у браузері

- Pyodide з jsdelivr (зафіксована версія, напр. `v0.26.4`), завантажується ліниво — лише коли учень уперше натискає «Запустити»/«Перевірити»; поки вантажиться — статус «Завантажую Python (≈10 МБ, лише перший раз)…».
- Виконання у Web Worker; тайм-аут 3 с на запуск, після якого worker знищується й створюється заново; повідомлення «Програма працює надто довго — можливо, нескінченний цикл».
- Вивід збирається з stdout/stderr; помилка Python показується останнім рядком трасування українською підказкою для частих випадків (`NameError`, `TypeError`, `IndentationError`, `SyntaxError`, `ZeroDivisionError`, `IndexError`).
- Порівняння виводу: рядки без кінцевих пробілів, без порожніх рядків наприкінці; числа порівнюються як текст (як надрукував Python), окрім задач, де дані задачі явно дозволяють допуск для `float`.
- Якщо Pyodide не завантажився або `file://`: повідомлення і кнопка «Скопіювати умову й дані», щоб розв'язати в ЄPython/Colab.

## Формат задачі

`data/taskbook/<тема>.js` додає до `window.TASKBOOK[<тема>]`:
`{id, title, emoji, source: {author: "Крутяк Н. О.", ref: "Тема_19 №1"} | null, text, vars: {назва: значення}, starter, tests: [{vars, out}], hint, tolerance?}`.
Перший тест збігається з прикладом із умови. Еталонні розв'язки лежать у `taskbook/solutions/<тема>/<id>.py`; скрипт `npm run check-tasks` (потрібен локальний `python3`) підставляє кожен набір `vars`, запускає розв'язок і звіряє з `out`; тест vitest перевіряє структуру даних. Рішення класти розв'язки в публічний репозиторій — компроміс: учні, які полізуть у код, їх знайдуть (так само як відповіді вікторин у JS).

## Теми задачника на цей етап

| Тема (`id`) | Уроки | Джерело | Задач |
|---|---|---|---|
| `types` — типи й арифметика | 18 | нові | 8 |
| `branching` — розгалуження | 19–20 | Крутяк, Тема_18 (10) + Тема_19 (12) | ~20 |
| `slices` — індекси й зрізи | 21–22 | Тема_20 (приклади) + нові | 10 |
| `list-ops` — операції та методи списків | 23–24 | Тема_21 (11) + нові | ~12 |
| `for-range` — `for`, `range`, `enumerate` | 25 | Тема_22 (12) | ~12 |

Задачі з ноутбуків переносяться за змістом (умова може бути трохи скорочена); дубльовані й ті, що виходять за тему уроку, можна пропустити.

## Уроки

Кожен урок — 45 хв, учительська картка з таймлайном на 45 (hook, теорія, 1–2 відступи з `projector`, практика в задачнику, обговорення, підсумок), ресурси: відповідний ноутбук Крутяк (посилання на папку), ЄПython, тема задачника. Метафори — пропозиція, будівельник може змінити, зберігши суть:

- **18 «Митниця типів»** — вирази-картки (`"3" + 4`, `7 / 2`, `7 // 2`, `-7 // 2`, `7 % 3`, `int("3.5")`, `float("3.5")`, `"3" * 3`, `2 ** 10`, `round(2.5)`): поставити штамп типу результату або «Помилка», потім значення; пастки `-7 // 2 == -4`, `round(2.5) == 2`, `int("3.5")` → `ValueError`.
- **19 «Диспетчерська розвилок»** — трасування: дано код із `if/elif/else` і значення змінних, учень вибирає, який рядок надрукується (підсвічування шляху); конструктор таблиці істинності `and/or/not`; пастки: порядок `elif` (`>= 7` перед `>= 10`), `=` замість `==`.
- **20 «Тестувальник»** — дано «майже правильні» розв'язки (високосний рік без умови про 400, максимум трьох з `>` замість `>=`, FizzBuzz з неправильним порядком): учень підбирає вхідні дані, на яких програма помиляється (перевірка в JS-моделі, без Pyodide); далі — задачник `branching`.
- **21 «Потяг-список»** — вагони з індексами `0…n-1` і `-1…-n`; повзунки `start/stop/step` показують зріз і вираз `a[start:stop:step]`; «передбач зріз» (`a[1:4]`, `a[-2:]`, `a[::-1]`, `a[::2]`, `a[5:1]`); пастка: `stop` не входить, `a[10]` → помилка, а `a[2:10]` — ні.
- **22 «Зріж точно»** — дано список і ціль (підпослідовність), учень пише найкоротший зріз, який її дає (перевірка семантикою зрізів у JS); далі — задачник `slices`.
- **23 «Склад списків»** — `+`, `*`, `in`, `len`, `min/max/sum`, порівняння списків; «передбач результат»; пастка для поглибленого рівня: `b = a; b.append(1)` змінює і `a`.
- **24 «Робот-комірник»** — послідовність методів (`append`, `insert`, `remove`, `pop`, `sort`, `reverse`, `index`, `count`) анімується над списком-полицею; учень передбачає стан після кожного кроку; пастки: `a = a.sort()` → `None`, `remove` видаляє перше входження, `pop()` повертає елемент.
- **25 «Лічильник range»** — повзунки `start/stop/step` показують числа `range`; «передбач» (`range(5)`, `range(2, 10, 3)`, `range(10, 0, -3)`, `range(5, 1)`); таблиця трасування циклу з накопиченням суми; пастка: `stop` не входить, порожній `range`.

На уроках, де доречно, «передбач вивід» має кнопку «Перевірити запуском» (Pyodide), але бал дається за передбачення, а не за запуск.

## Інтеграція з сайтом

## Обмеження

- Тексти українською, друга особа однини, обидві форми роду, де дієслово цього вимагає.
- `--accent` курсу — на вибір будівельника, один для всіх восьми уроків і задачника.
- Усе клікабельне — справжні `<button>`, працює з клавіатури й на телефоні (ширина ≈400 px).
- `verified` у ресурсах — лише для посилань, які справді відкрили.
- Без нових залежностей у збірці (її немає); vitest/jsdom уже є.

## Залишено будівельнику

Точні тексти пояснень і пасток, вибір і скорочення задач з ноутбуків, приховані набори даних (з крайніми випадками), розкладка сторінок, назви папок уроків (`NN-py-<slug>`), кольоровий акцент, деталі повідомлень про помилки, межі тайм-ауту в межах 2–5 с.

## Рішення, ухвалені без користувача (перевірити)

- Задачі Крутяк публікуються з підписом і посиланням на папку; дозвіл авторки користувач погоджує сам до публікації на GitHub Pages.
- Еталонні розв'язки лежать у публічному репозиторії.
- Pyodide, а не Skulpt/Brython: повний CPython, точні результати й помилки.

## Уточнення після перевірки будівельником

Рішення автора документа (не користувача) — перевірити під час читання:

1. **Звідки Pyodide.** CDN jsdelivr, не в репозиторії. Worker — власний файл того самого походження `assets/py/worker.js` (класичний worker), який робить `importScripts("https://cdn.jsdelivr.net/pyodide/v0.26.4/full/pyodide.js")`. На `file://` або без мережі worker/завантаження падає → показується fallback «Скопіювати умову й дані». «Працює без інтернету» стосується всього, крім запуску коду.
2. **Задачі Крутяк** входять у дані одразу, кожна з `source`; окремого прапорця не робимо. Дозвіл авторки користувач погоджує до пушу.
3. **Перенесення задач.** Кожна задача — змінні в «Вхідних даних» + `print` результату; формулювання авторки зберігається, скорочується лише там, де воно описує `input()` чи зайве оформлення. Якщо в ноутбуці є «Очікуваний результат» — він стає першим тестом; решта тестів (2–4 приховані, з крайніми випадками) придумуються й рахуються еталонним розв'язком. Кількість задач — як у таблиці, ±3 на тему.
4. **Порівняння виводу.** Порядково: кінцеві пробіли в рядку й порожні рядки наприкінці ігноруються, пробіли всередині рядка значущі. `tolerance` (якщо задано) застосовується до кожного числового токена рядка. Умови задач, що друкують `float`, явно вимагають `round(…, 2)` або f-рядок, щоб уникнути `0.30000000000000004`.
5. **«Перевірити запуском» на уроках.** Той самий модуль `assets/py/runner.js`; кнопка видима завжди, при першому натисканні вантажить Pyodide, у разі невдачі показує пояснення (бал за передбачення від цього не залежить). Повторне завантаження на іншій сторінці береться з кешу браузера.
6. **Прогрес і сторінка курсу.** `localStorage` ключ `taskbook-v1`, значення `{<тема>: {<id>: true}}`, доступ у `try/catch`. Сторінка курсу завантажує лише маленький `data/taskbook/index.js` (список тем: id, назва, уроки, кількість задач); `programs.js` отримує `taskbook: true` для `inf10deep`. `assets/teacher.js` і `teacher/index.html` не змінюються — картки посилаються на задачник через `resources` і `link` таймлайну (повний шлях `../../taskbook/index.html#<тема>` у `resources`; у таймлайні лише `#…` на власні вкладки).
7. **`check-tasks`.** `npm run check-tasks` — локальний скрипт розробника (потребує `python3`), не входить у `npm test`. `npm test` перевіряє лише структуру даних задачника й наявність файлу розв'язку для кожної задачі.
8. **Спільні модулі** — `assets/py/`: `runner.js` (worker, тайм-аут, завантаження), `compare.js` (порівняння виводу), `errors.js` (українські підказки до помилок), `slice.js`, `range.js`, `listsim.js` (семантика для уроків 21–25). Тестуються vitest, як `assets/boards/*`.
9. **Акцент** — один для всіх уроків курсу й задачника (на вибір будівельника, не оранжевий «Розумних плат»).
10. **Учительські картки** — у форматі `lessons/15-boards-rgb/teacher.html` і записів `"boards:15"`.
